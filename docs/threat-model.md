# Threat model

This page lists the security controls the code enforces today. Add a row whenever a change adds a control, together with the test that proves it.

## Why this matters

Tessaly runs with your user's rights. Treat anyone who reaches the Tessaly API as able to act as you on your machine. Every route, file path and command is a security boundary.

## Controls

| Threat | Control | Test |
| --- | --- | --- |
| Another device on the network reaches the API | `tess serve` binds to `127.0.0.1` by default. `--listen` takes a plain IP address for containers, which must publish the port on the host's `127.0.0.1`, and tess warns on stderr when it binds wider. Whatever the bind, the Host check below only accepts `127.0.0.1` and `localhost`. | `TestAddr`, `TestIsLoopback`, `TestRun`, `TestServeListenWarnsOffLoopback` |
| DNS rebinding: a web page points its own domain at `127.0.0.1` | Requests whose `Host` header is not `127.0.0.1:<port>` or `localhost:<port>` get `403` | `TestHostCheck` |
| Another OS user or local process calls the API | Every `/api/` route except sign-in and sign-out needs a session. You get one with a passkey, or by posting the login token, 32 random bytes kept in `~/.tessaly/token`. Tokens compare in constant time. Once a passkey exists, the token signs in only with `--allow-token-login`. | `TestAPINeedsSignIn`, `TestAPILoginFlow`, `TestLoginRejectsBadBodies`, `TestPasskeyRegisterAndSignIn`, `TestAllowTokenLoginKeepsTokenOn` |
| A forged, replayed or phished passkey sign-in | WebAuthn through `go-webauthn/webauthn`, with user verification required. The site is `localhost` and the only accepted origin is `http://localhost:<port>`, so a local server on another port that asks the browser to sign gets refused. Each ceremony has a random ID, works once, lasts 2 minutes, and is tied to its kind and to the session that started it. A sign counter that goes backwards is refused as a possible clone. At most 32 ceremonies stay open. Refused passkeys count toward the sign-in limit. | `TestPasskeySignInRefuses`, `TestPasskeysNeedLocalhost`, `TestRegisterRefuses`, `TestCeremoniesAreCapped`, `TestPasskeyFailuresCountTowardTheLimit`, passkey E2E |
| Someone with the token or a stolen session swaps in their own passkey | Adding a second passkey and removing one need a passkey check from the last 5 minutes, through `RequireFresh`. Removing a passkey ends the sessions it signed in. Passkeys hold only public keys, and each install has its own random WebAuthn user ID. | `TestChangingPasskeysNeedsAFreshCheck`, `TestDeletingAPasskeyEndsItsSessions`, `Passkeys.test.tsx` |
| Another server on `127.0.0.1` gets the session cookie | Browsers send cookies for `127.0.0.1` to every port on it. So a session has two halves: the cookie, and a session key the login reply returns. The UI keeps the key in `localStorage`, which belongs to one origin, port included, and sends it in the `X-Tessaly-Key` header, or as a WebSocket subprotocol for the terminal. The API needs both halves, so a server on another port that receives the cookie cannot use it. | `TestRequireNeedsCookieAndKey`, `TestRequestKey`, `TestAPILoginFlow`, `TestTerminalRejects`, `apiFetch` tests, E2E |
| Someone guesses the token | The token has 256 bits of randomness. After 10 failed sign-ins in a minute, tokens and passkeys together, sign-in replies `429` to every attempt until the minute ends. | `TestLoginLimitsWrongTokens`, `TestLoginRightTokensAreNotLimited` |
| Other users read the token | The data folder must be mode 0700 and the token file 0600, and a symlinked or malformed token file is refused. `tess serve` stops with an error otherwise. | `TestEnsureHome`, `TestLoadOrCreateTokenRejectsUnsafeFiles`, `TestServeRefusesOpenHome` |
| The token lands in log files | `tess serve` prints the sign-in link with the token only when stdout is a terminal. The token rides in the URL fragment, which browsers never send to the server, and the UI removes it from the address bar. Otherwise it prints only the token file path. | `TestServeStopsOnCancel`, `takeTokenFromHash` tests |
| Session theft through scripts | The session cookie is `HttpOnly` and `SameSite=Strict`, so a script that reads the session key still lacks the cookie. The CSP keeps scripts to Tessaly's own bundle. Sessions last 7 days and live only in memory, so a daemon restart ends every session. The cookie and the key are 32 random bytes each, stored only as SHA-256 hashes, and the key compares in constant time. Sign out deletes the key from the browser. | `TestAPILoginFlow`, `TestSessionExpires`, `authApi` tests |
| CSRF: a web page you visit posts to the local API | `http.CrossOriginProtection` rejects non-GET requests that the browser marks cross-site through `Sec-Fetch-Site`, or whose `Origin` does not match the host. `SameSite=Strict` keeps the cookie off cross-site requests too. | `TestAPIRejectsCrossSiteRequests` |
| A crafted repo path reaches git or the file system | `POST /api/v1/repos` takes only an absolute path. Tessaly resolves symlinks, checks it is a folder, and accepts it only when `git rev-parse --show-toplevel` from inside it returns the same folder. Subfolders, bare repos and flag-like values such as `--help` are refused. Git runs with a fixed argv, no shell, a 30 s timeout and `GIT_TERMINAL_PROMPT=0`. Removing a repo deletes only its record, never files. | `TestRepoRoot`, `TestRepoRootRejects`, `TestReposAPIRejectsBadInput` |
| A workspace name injects git flags, shell syntax or path segments | Names must match `^[a-z0-9][a-z0-9-]{0,47}$`, so they cannot start with `-` or hold `/`, `..` or spaces. Git calls put `--` before paths, and the worktree path is checked to stay inside `~/.tessaly/worktrees`. | `TestValidSlug`, `TestWorktreePathStaysInRoot`, `TestWorkspacesAPIRejectsBadInput` |
| Tessaly overwrites or deletes your work | Each workspace gets a new `tess/<name>` branch, and an existing branch is never reused. Archiving runs `git worktree remove` without `--force`, so a worktree with uncommitted or untracked files is refused, and only paths git lists as the repo's worktrees are removed. The branch stays. A repo with workspaces cannot be removed. | `TestCreateRefuses`, `TestArchiveRefusesDirtyWorktree`, `TestCreateMarksFailure`, `TestWorkspacesAPI` |
| Reviewing a diff runs code from the repo, or a huge diff exhausts memory | The diff runs `git diff --no-ext-diff --no-textconv`, so `diff.external` and textconv drivers from repo config never run. The base must be a full commit hash, so it cannot pass a flag. Output stops at 1 MiB and 500 new files. The UI renders the diff as text, never as HTML. | `TestDiffIgnoresExternalDiffConfig`, `TestDiffRejectsBadBase`, `TestDiffStopsAtLimit`, `Changes.test.tsx` |
| Tessaly leaks or stores your GitHub credentials | Tessaly holds no token. It runs `gh` and `git push` as you, so gh keeps its token in your OS keychain or its own config. Git and gh run in a new session with no terminal, `GIT_TERMINAL_PROMPT=0` and `GH_PROMPT_DISABLED=1`, so nothing waits for a password. Error text shown in the UI has the user and password of any remote URL replaced by `***`. | `TestPushErrorHidesCredentials`, `TestRedact`, `TestOpenPRErrors` |
| Shipping injects flags, rewrites history or links to a hostile URL | The commit message goes to `git commit --file=-` on stdin, the title is one `--title=` argument and the description goes to gh on stdin. The push never forces and names `refs/heads/tess/<name>` in full. Only an `https` URL without user info from gh is stored and linked, with `rel="noopener noreferrer"`. A ship refuses while an agent runs, and archive refuses while a ship runs. | `TestCommitAllAndPush`, `TestPushNeverForces`, `TestOpenPR`, `TestShipRefuses`, `Ship.test.tsx` |
| Check status links to a hostile page or floods the daemon | Only `https` check links without user info reach the UI, opened with `rel="noopener noreferrer"`. gh is asked once a minute per open pull request, one at a time, and at most 100 checks are kept per pull request. | `TestChecks`, `TestUpdate`, `Ship.test.tsx` |
| Other users read agent work | Worktree folders are created with mode 0700 under the private data folder. | `TestCreateAndArchive` |
| The API runs a program of the caller's choice | The API only names an agent. The argv for each agent comes from `~/.tessaly/config.toml` on the host, and Tessaly refuses that file if other users can write it. Unknown request fields, such as `command`, are rejected. Resume runs only the agent's own `resume` argv from the same file, takes no request body, and works only on a run that tess cut off. | `TestLoadRejects`, `TestAgentStartRejects`, `TestAgentResumeAPI`, `TestAgentResumeNeedsResumeCommand` |
| Other users read prompts in the process list | An agent whose command holds `{prompt_file}` gets the path of a file instead of the prompt. The file is written with mode 0600 in the 0700 `~/.tessaly/prompts` folder without following symlinks, only after the start checks pass, and is deleted when the agent exits or fails to start. | `TestGenericCommandWithPromptFile`, `TestStartWritesPromptFileAndRemovesIt`, `TestStartLeavesARunningAgentsPromptAlone`, `TestAgentRunAPIWithPromptFile` |
| Shell injection through the prompt | Agents run from an argv array with no shell. The prompt replaces only an argv element that is exactly `{prompt}`, so it stays one argument whatever it holds. Prompts over 32 KiB or with NUL bytes are refused. | `TestGenericCommand`, `TestGenericCommandRejectsBadPrompts`, `TestAgentRunAPI` |
| An agent reaches Tessaly's own settings or another repo | Agents start in their worktree with the daemon's environment minus `TESSALY_*` and `GIT_*` variables. | `TestStartRunsAgentInWorktree`, `TestAgentEnv` |
| Agents outlive the daemon or ignore Stop | Each agent leads its own process group. Stop sends SIGTERM to the group, then SIGKILL after 10 s. `tess serve` stops every agent before it exits, and marks agents left running by a crash as exited on the next start. | `TestStopEndsProgramAndChildren`, `TestStopAndStopAll`, `TestRecover` |
| A web page you visit opens the terminal socket | The socket needs both halves of a session, and `websocket.Accept` refuses an `Origin` that does not match the host. The `SameSite=Strict` cookie is not sent on cross-site requests either. The server picks the plain `tessaly` subprotocol, so it never echoes the key. Browser messages are capped at 64 KiB and resizes at 500 by 1000. | `TestTerminalRejects`, `TestTerminalStreamsAndTakesInput` |
| Agent output runs as script in the UI | Output is served as `text/plain` with `nosniff`. The terminal socket sends it as binary, which xterm.js draws as terminal cells, never as HTML, and the UI ignores text messages from the server. | `TestAgentRunAPI`, `terminalSession` tests |
| Other users read transcripts | Transcripts are kept in `~/.tessaly/logs/workspace-<id>.log` with mode 0600 in a 0700 folder. | `TestStartRunsAgentInWorktree` |
| Agents fill the disk or memory | A transcript stops at 64 MiB, and the next run moves it to `.log.1`, so each workspace keeps at most two. At most 16 agents run at once, each with 1 MiB of output in memory, and starting one more replies `429`. | `TestTranscriptStopsAtLimitAndRotates`, `TestStartCapsRunningAgents` |
| Malformed or oversized API requests | JSON routes need `Content-Type: application/json`, cap bodies at 64 KiB and reject unknown fields. Errors reply with a short message, and internal errors are logged, not returned. | `TestReposAPIRejectsBadInput` |
| Other users read Tessaly's state | `tessaly.db` is created with mode 0600 inside the 0700 data folder. SQL uses bound parameters only. | `TestOpenCreatesPrivateFileAndMigrates` |
| Clickjacking or content injection in the UI | `Content-Security-Policy` that allows scripts only from Tessaly itself (`script-src 'self'`, no inline or eval). Inline styles are allowed because the terminal needs them, and they cannot run code. Also `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and a `Permissions-Policy` that turns off camera, microphone, location, USB and payments and keeps passkeys to this origin, on every response | `TestSecurityHeaders`, `TestCSPKeepsScriptsStrict` |
| Reading files outside the UI bundle | The UI is served from an embedded, read-only file system. The server indexes the bundle once at start and serves only files in that index, so folders are never listed and dotfiles and `..` paths return `404`. | `TestUI`, `TestUIPathTraversal` |
| Slow clients holding connections open | Read, write, header and idle timeouts, and a 64 KiB header limit | Covered by the `Serve` config |
| Someone on the network or a web page resets sign-in | No HTTP or WebSocket route resets sign-in. `tess auth reset` runs on the host and talks to the daemon over a Unix socket in `~/.tessaly/run`, mode 0600 in a 0700 folder. The daemon checks the caller's user ID with `SO_PEERCRED` on Linux and `LOCAL_PEERCRED` on macOS and refuses other users. The socket reads one command of at most 256 bytes from a fixed list, and errors do not carry details. | `TestCall`, `TestPeerUIDIsOurs`, `TestServeRefusesLongCommands`, `TestCallReportsFailureWithoutDetails`, `TestLockRefusesAnOpenFolder` |
| A reset leaves a way back in | A reset writes a new token with one rename, swaps the daemon's token hash, ends every session and open passkey prompt, and deletes every passkey with an audit row in one transaction. With the daemon stopped, a lock file shows it is safe to change the files directly, and a second daemon on the same folder is refused. The new token signs in once, within 15 minutes, and its used state is kept in `tessaly.db` so a restart does not reopen it. The command asks you to type the host name. | `TestResetEndsSessionsAndSwapsToken`, `TestResetTokenExpires`, `TestPendingResetStartsOnEnable`, `TestAuthResetWhileRunning`, `TestAuthResetWhileStopped`, `TestAuthResetNeedsConfirmation`, `TestServeRefusesASecondDaemon`, reset E2E |
| An agent resets sign-in to get a working token | The daemon reads the caller's process ID from the socket (`SO_PEERCRED`, `LOCAL_PEERPID`) and refuses the reset when the caller shares a session with, or descends from, an agent Tessaly started. When it cannot read the process tree, it refuses. | `TestResetRefusesAgents`, `TestInTree`, `TestCallPassesRefusals` |
| A reset goes unnoticed | Every session ends, the reset writes an audit row and a warning log, and the next person to sign in sees a notice with the time until they dismiss it. | `TestResetNotice`, `ResetNotice` unit tests, reset E2E |
| A tampered CI action or dependency | Actions pinned to full commit SHAs, `contents: read` permissions, `persist-credentials: false`, a frozen pnpm lockfile, install scripts off, `govulncheck` in CI, and Dependabot updates | CI |
| The install script downloads a swapped binary | The script takes only a version like `v1.2.3`, downloads over HTTPS and refuses redirects to anything but HTTPS. It checks the archive's SHA-256 against `checksums.txt` and, when cosign is installed, the signature on `checksums.txt`. It never uses sudo and moves the binary into place in one step. | `scripts/install_test.sh` |
| A tampered or forged release | Releases build only from `v*` tags on commits already on `main`, in a job with only `contents`, `id-token` and `attestations` write rights, pinned actions, an exact GoReleaser version and no caches. `checksums.txt` has a keyless cosign signature tied to the release workflow, each archive has a build provenance attestation and an SBOM, and the release stays a draft until a maintainer publishes it. The image is signed with cosign by digest and gets a provenance attestation and an SBOM. Its base image is pinned by digest and it runs as a non-root user. The Homebrew tap is written with a token that can only write that one repo, kept in the `release` environment. A snapshot build on every pull request checks that the UI is embedded. | Release workflow, CI snapshot |

## Known gaps

These are open risks in the code today. Each one needs a fix or a decision before v1.0.

| Gap | Why it matters |
| --- | --- |
| Committing runs the repo's git hooks | Opening a pull request runs `git commit`, so hooks in the repo run as you. An agent in the workspace could have changed them. This is the same trust as the agent itself. |
| Agents run with your full user rights | There is no sandbox yet. An agent can read and change any file you can, not only its worktree. Use the agent's own permission settings. |
| A local process can keep sign-in closed | Ten failed sign-ins a minute close sign-in for everyone, and 32 open passkey prompts block new ones for 2 minutes, so a process on your machine can keep you from signing in. Sessions already signed in keep working. Failed token sign-ins are logged, without the token. |
| A process running as you can reset sign-in | Agents are refused, but any other program that runs as your OS user can run `tess auth reset`, or a process that detaches from its agent's session and parent. Such a program could already change `tessaly.db` and the token file, so the command adds no new power. The reset ends every session, writes an audit row, shows a notice at the next sign-in, and prints the new token only to a terminal. |
| `{prompt}` shows in the process list | An agent that takes the prompt as `{prompt}` gets it as an argument, so other users on the machine can see it with `ps`. Use `{prompt_file}` where the CLI can read a file. If Tessaly crashes while an agent runs, its prompt file stays in `~/.tessaly/prompts` (mode 0600) until that workspace runs an agent again. |
